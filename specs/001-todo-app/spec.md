## User Scenarios & Testing

### Primary User Story
사용자는 해야 할 일을 빠르게 기록하고, 전체 목록을 최신 등록순으로 한눈에 확인하며, 완료한 항목을 표시하고, 더 이상 필요 없는 항목을 확인 후 삭제할 수 있다. 별도 로그인 없이 단일 사용자가 사용하는 공용 목록이다.

### Acceptance Scenarios
1. **Given** 할 일 목록이 비어 있음, **When** 사용자가 제목을 입력하고 추가 요청을 보냄, **Then** 새 할 일이 완료되지 않은 상태(`done: false`)로 목록 맨 위에 추가된다.
2. **Given** 할 일이 여러 개 존재함, **When** 사용자가 목록을 조회함, **Then** 등록된 모든 할 일이 최신 등록순으로 제목과 완료 여부와 함께 표시된다.
3. **Given** 완료되지 않은 할 일이 존재함, **When** 사용자가 해당 항목의 완료 토글을 요청함, **Then** 해당 항목의 완료 여부가 반대 값으로 변경된다(다시 토글하면 원래대로 돌아간다).
4. **Given** 할 일이 존재함, **When** 사용자가 해당 항목의 삭제를 요청하고 확인함, **Then** 해당 항목이 목록에서 제거되고 이후 조회 시 나타나지 않는다.
5. **Given** 사용자가 삭제를 요청함, **When** 확인 절차에서 취소함, **Then** 해당 항목은 삭제되지 않고 목록에 그대로 남는다.
6. **Given** 할 일 추가 시 제목을 입력하지 않음, **When** 사용자가 추가를 요청함, **Then** 요청이 거부되고 제목이 필수임을 알리는 에러가 반환된다.
7. **Given** 완료/미완료 항목이 섞여 있음, **When** 사용자가 "미완료" 또는 "완료" 필터를 선택함, **Then** 해당 상태의 할 일만 목록에 표시된다.
8. **Given** 할 일을 추가할 때 우선순위를 지정하지 않음, **When** 추가 요청이 처리됨, **Then** 해당 할 일의 우선순위는 "Medium"으로 설정된다.
9. **Given** 할 일이 존재함, **When** 사용자가 해당 항목의 우선순위를 다른 값으로 변경함, **Then** 변경된 우선순위가 해당 항목에 반영되고 다른 필드(완료 여부 등)는 영향받지 않는다.

### Edge Cases
- 제목이 공백 문자로만 이루어진 경우 → 유효하지 않은 제목으로 취급한다.
- 존재하지 않는 할 일 ID에 대해 토글/삭제를 요청하는 경우 → 실패 응답(찾을 수 없음)을 반환한다.
- 동일한 제목의 할 일을 여러 번 추가하는 경우 → 허용한다(제목 중복 금지 규칙 없음).
- 필터가 "완료" 또는 "미완료"로 선택된 상태에서 해당 조건에 맞는 항목이 하나도 없는 경우 → 빈 목록을 표시한다.

## Requirements

### Functional Requirements
- **FR-001**: 시스템은 사용자가 제목을 입력하여 새 할 일을 추가할 수 있어야 한다.
- **FR-002**: 시스템은 제목이 비어 있거나 공백뿐인 할 일 추가 요청을 거부해야 한다.
- **FR-003**: 새로 추가된 할 일의 완료 여부 초기값은 "미완료"여야 한다.
- **FR-004**: 시스템은 등록된 모든 할 일의 목록(제목, 완료 여부 포함)을 최신 등록순(내림차순)으로 조회할 수 있어야 한다.
- **FR-005**: 시스템은 특정 할 일의 완료 여부를 토글(미완료↔완료)할 수 있어야 한다.
- **FR-006**: 시스템은 특정 할 일을 목록에서 삭제할 수 있어야 한다.
- **FR-007**: 존재하지 않는 할 일에 대한 토글/삭제 요청은 실패로 처리되어야 한다.
- **FR-008**: 시스템은 목록을 전체/미완료/완료 상태로 필터링하여 조회할 수 있어야 한다.
- **FR-009**: 시스템은 삭제 요청 시 사용자에게 확인을 요구하고, 확인된 경우에만 실제로 삭제를 수행해야 한다.
- **FR-010**: 시스템은 로그인 없이 단일 사용자가 사용하는 하나의 공용 할 일 목록만 제공해야 한다(사용자별 목록 분리 없음).
- **FR-011**: 시스템은 할 일마다 우선순위(High/Medium/Low)를 가져야 한다.
- **FR-012**: 할 일 추가 시 우선순위를 생략하면 기본값 "Medium"이 적용되어야 한다.
- **FR-013**: 시스템은 생성된 할 일의 우선순위를 이후에도 변경할 수 있어야 한다.
- **FR-014**: 우선순위는 목록의 정렬이나 필터링 기준으로 사용하지 않으며, 각 항목에 시각적으로 표시하는 용도로만 사용한다.
- **FR-015**: 유효하지 않은 우선순위 값으로의 추가/변경 요청은 거부되어야 한다.

### Key Entities
- **Todo(할 일)**
  - `title` (문자열, 필수, 공백 불가): 할 일의 제목
  - `done` (불리언, 필수): 완료 여부, 기본값 `false`
  - `priority` (문자열 열거형, 필수): High/Medium/Low 중 하나, 기본값 `Medium`, 생성 후 변경 가능
  - `createdAt` (일시, 필수): 등록 시각 — 목록의 최신 등록순 정렬 기준
